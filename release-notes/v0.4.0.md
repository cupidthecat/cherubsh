# CherubSH 0.4.0

CherubSH 0.4.0 expands the evidence behind its Bash and Readline compatibility claims. Platform support remains limited to Linux and WSL.

## Compatibility and testing

- A reusable PTY differential harness now compares the interactive shell with pinned Bash. It covers terminal resizing, suspend and resume, foreground and background pipelines, EOF, Unicode editing, bracketed paste, Emacs and Vi modes, completion, and interrupt recovery.
- The previously skipped Brush background-job, coprocess, trap, and `read` cases are now classified and run when deterministic. Selected Bash miscellaneous scripts also have automated comparisons.
- Persistent fuzz targets cover the lexer, parser, expansion, line-input decoding, and the Readline FFI boundary. Saved failures become regression seeds, and scheduled benchmarks retain raw results without imposing premature thresholds.

## Builds and libraries

- Release and parity jobs now run natively on x86-64 and AArch64. Shell identity values and version banners come from the compiler target rather than a fixed architecture string.
- The Readline and History development archive contains headers, shared-library links, static archives, and `pkg-config` metadata. Its installer supports `PREFIX`, `DESTDIR`, component selection, and uninstall without removing unrelated files.
- ABI tests compare constants, structure size and layout, allocation ownership, callback lifecycles, redisplay hooks, streams, completion, inputrc conditions, and saved History state with GNU Readline 8.3 patch 3.

## Releases and maintenance

- The package version is reported separately from the Bash compatibility version. Tags are checked against Cargo metadata before release builds begin.
- Release supply chain checks now include dependency review, RustSec audits, CycloneDX SBOMs, SHA-256 manifests, pinned workflow actions, and GitHub artifact attestations.
- The release archives include manual pages, command completion, starter configuration, and prefix-aware installation tools. Contributor guidance, security reporting, issue templates, and the changelog are available at the repository root.
- Large shell-state, parameter-expansion, interactive-reader, and Readline FFI files were split into focused module boundaries after their behavior was covered by the stronger gates.
